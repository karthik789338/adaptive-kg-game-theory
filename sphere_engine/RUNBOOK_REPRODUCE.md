# EC-POMDG — full reproduction runbook (testbed → KGs → Neo4j → experiments)

End-to-end sequence to rebuild the SPHERE testbed, regenerate the three
knowledge graphs, load Neo4j, stand up live KG enrichment, and produce the H1/H2
+ ablation results. Every step below was executed and verified on the
`ecpomdgfinalv2` testbed on 2026-10-17.

The patched versions of the original setup scripts are under `setup_patches/`;
each must replace its namesake in `~/ecpomdg_setup/<component>/` on the XDC host
before the step that uses it. `SETUP PATCH:` lines below say which.

Prereqs: `~/ecpomdg_setup` and `~/backup_dir` restored on the XDC host; ssh to
all nodes (attacker, controller, decoy, collector, gridsim, defender, kg).

---

## Phase 0 — testbed + application stack

```bash
cd ~/ecpomdg_sphere
bash pipeline/deploy_all.sh          # gridsim plant (reconstructed) FIRST, then endpoints,
                                     # telemetry, attacker, decoy multistage sensor, engine
```

  voltage model. Deploy step 0 (before the controller, which reads `/state` on boot).
- `multistage_game/deploy_and_validate_decoy_live_multistage_sensor.sh` — (a) restore the
  real `c104.Server` class before `install_multistage_sensor` so callback annotations pass
  c104 2.2.1 validation; (b) guard the operational-observation baseline `wc -l` against a
  missing file.
- `multistage_game/deploy_and_validate_multistage_belief_runtime.sh` — ship the full
  `ec_pomdg` engine package + configs to the defender (it runs the belief runtime).

## Phase 1 — three KGs → Neo4j

```bash
# 1. build the 3 KGs on the kg node (downloads MITRE ATT&CK/ICS, CAPEC, CWE, CISA KEV)
bash pipeline/phase1_build_kg.sh         # creates the shared KG venv, then builds + freezes

# 2. install + start Neo4j, then import the 3 KGs (non-interactive)
cd ~/ecpomdg_setup/neo4j_knowledge_graph_migration
bash install_neo4j_community_on_kg.sh          # Java 21 + Neo4j 2026.09.0
bash repair_neo4j_duplicate_configuration.sh   # dedupe conf (server.https.enabled etc.)
export NEO4J_PASSWORD='<min 12 chars>'
bash ~/ecpomdg_sphere/pipeline/phase1_neo4j_up.sh   # set password, start, import
```
SETUP PATCHES used by this phase:
- `power_grid_component_topology_knowledge_graph/build_power_grid_component_topology_knowledge_graph.sh`
  — use the frozen IEEE-13 snapshot from `backup_dir` instead of re-capturing via the lost
  OpenDSS venv on gridsim.
- `general_cyber_knowledge_graph/build_general_cyber_knowledge_graph.sh` — exclude
  `Status==Deprecated` CAPEC (56) and CWE (25) so the graph is active-only (CAPEC 559 /
  CWE 944), and relax the stale exact-count assertions.
- `neo4j_knowledge_graph_migration/import_frozen_knowledge_graphs_into_neo4j.py` — read the
  password from `NEO4J_PASSWORD`; compute totals dynamically instead of asserting the old
  fixed 6742/33630; drop the per-source hard counts (keep file↔summary consistency).
- `pipeline/phase1_build_kg.sh`, `pipeline/phase1_neo4j_up.sh` — new non-interactive
  orchestration (venv prep, source-reachability preflight, start+import).

Result: Neo4j on 127.0.0.1:7687 with 6756 nodes / 33667 rels
(general_cyber 6185, power_grid_ics 467, component_topology 104), all active-only.

## Phase 3 — live online-Neo4j pre-decision episode

Run on the XDC host, in order. Interactive steps prompt for the Neo4j password
on `kg`'s TTY — do not pipe their output.

```bash
cd ~/ecpomdg_sphere
bash pipeline/phase3_real_sensor.sh          # 1. switch real controller -> source-derived _v2 multistage endpoint
bash pipeline/phase3_operational_collector.sh # 2. hardened collector (operational flow + IEC-104 command-field whitelist)
bash pipeline/phase3_sensor_forwarder.sh      # 3. real sensor -> collector forwarder (enveloped; --mode real)
bash pipeline/phase3_build_bridges.sh         # 4. build the 5 Topology<->ICS semantic bridges in Neo4j
bash pipeline/phase3_deploy_episode.sh        # 5. deploy phase3d2a code + SELECT probe; self-tests
bash pipeline/phase3_live_episode.sh          # 6. run the live NO_KG integration episode
```

SETUP PATCHES used by this phase (apply before step 2; copy each over its
namesake on the XDC host as in Phase 0/1):
- `telemetry_ground_truth/telemetry_collector_service.py` — the hardened collector:
  adds the operational-observation write (the deploy-pipeline heredoc build omits it)
  AND whitelists the on-the-wire IEC-104 command fields `command_phase`, `asdu_type`,
  `cause`, `common_address` (the SELECT evidence the episode waits on).
- `multistage_game/live_multistage_sensor_build/multistage_live_sensor_forwarder.py` —
  the **enveloped** forwarder that POSTs `{"event": <dict>}`; the flat build is
  rejected by the hardened collector with HTTP 400.
- `multistage_game/iec104_real_select_only_probe.py` — the real SELECT-only probe
  (stdlib; deployed to the attacker by step 5); SELECT for IOA 100, never EXECUTE.
- `dynamic_knowledge_graph/manage_phase3d1c_neo4j_semantic_bridges.py` — the
  freeze-repinned bridge manager: live-core guard relaxed `== 6742/33630` → `>=`
  (the active-only graph is a superset of the original frozen core; `general_cyber`
  drifted and carries no bridges; the 5 bridges are new nodes outside `:KGNode`, so
  before == after still holds). Manifest + attestation are unchanged provenance.
- `dynamic_knowledge_graph/{validate_phase3d2a_live_neo4j_predecision_integration,
  ecpomdg_phase3d2a_online_kg_transport, ingest_and_query_phase3d2a_live_neo4j_observations}.py`
  + `phase3d1c_semantic_bridge_manifest.json` — the phase3d2a coordinator/transport/
  kg-worker and the bridge manifest, shipped to XDC/kg by steps 4–5.

Result: `PHASE3D2A_LIVE_NEO4J_PREDECISION_INTEGRATION: PASS` (exit 0), 12 online
episode observations committed and read back before the decision, 8 of them
Topology↔ICS bridged, frozen core + 5 bridges unchanged, real controller never
executes, plant unchanged. This is an integration/safety proof, not new KG
efficacy — see `RESULTS.md` (Phase 3) and `docs/KG_ATTACK_SEMANTICS.md`.
